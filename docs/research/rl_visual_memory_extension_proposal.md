# Proposed fixed continuation after the visual-memory pilot

This is a proposal, not an authorized launch or a frozen protocol. The current pilot must finish its entire fixed 25,024,000-frame curriculum first. Any extension starts from its final checkpoint, regardless of whether an earlier checkpoint scored better.

The final pilot checkpoint preserves the policy, original configuration, complete RMSProp state, optimizer step counters, and CPU/CUDA random-number states. These permit exact restoration of the learned parameters and optimizer. It does not preserve the live arena, recurrent state, saved goal, previous action/reward, or visual clock. Consequently, the proposed extension begins fresh native episodes and records that boundary explicitly. It is not a bitwise continuation of the same trajectories.

Use five fixed blocks of 782 original A2C updates, each comprising 32 environments × 100 decisions × four counted frames. That gives 10,009,600 frames per block and **50,048,000 additional learning frames per model**, ending at 75,072,000 learning frames beyond the original 1B checkpoint. The earlier 2,560,000 zero-LR exposure frames remain separately counted. Do not repeat the warmup: restore the existing RMSProp state and retain its learning rate and all other original settings.

Keep the original environment, goal distribution, native current/goal codes, six actions, reward and architecture. The final visual schedule remains fixed throughout: 15 visible updates, then an integer-uniform 30–60-update blackout after discovery, with each new reward renewing vision. There is no longer-gap curriculum and no new auxiliary objective. New environment and schedule RNG seeds are declared before launch; restore the saved global policy-sampling RNG after constructing the new environments.

Evaluate the incoming final checkpoint and all five block endpoints using the same six branches, 64 paired episodes, evaluation seed 98201, and final blackout schedule as the pilot. Check that the incoming checkpoint reproduces the pilot's final behavioral rows. Retain all endpoints; do not select or restart from a favorable intermediate result. Report absolute navigation scores, both own-checkpoint and original-baseline vision benchmarks, reset interactions, current-code replacement effects, and actual blackout exposure.

Implementation should live in a new script that imports the frozen pilot's clock, input masking, rollout and evaluation functions. It should load policy and optimizer strictly, compare their restored tensors and counters against the parent checkpoint, and save their incoming hashes. New checkpoints should additionally store the live environment tensors and RNG, current observations, `(h,c)`, goal snapshot, previous action/reward, visual-clock tensors/RNG, and episode counters. A split-versus-uninterrupted test should verify this stronger future resume format.

At the pilot's measured throughput of roughly 13,300 frames/s, the extension should take about 65–70 minutes per model including evaluations and startup. Two isolated T4 workers with the same two-hour provider DELETE limit require **$5.625 in total conservative reservations**, charged to the existing cumulative $500 authorization. No further workers or larger resource class are included in this proposal. Existing frozen pilot files stay unchanged.
